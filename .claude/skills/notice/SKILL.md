# 로스쿨 공지 확인

평소에는 GitHub Actions 가 30분마다 알아서 돌린다. 이 스킬은 **지금 당장**
확인하고 싶을 때, 또는 클라우드가 멈췄을 때 내 PC에서 대신 돌리는 용도다.

역할 분담은 이렇다. **파이썬이 모으고 보내고, Claude 는 본문을 읽고 판단한다.**

---

## 1단계 — 게시판 확인

```
python scrape.py
```

무엇을 봐야 하나:

- **`[실패]` 가 한두 개 있는 것은 정상이다.** 학교 서버가 가끔 끊는다.
  다만 5개 전부 실패했다면 네트워크 문제이니 여기서 멈추고 사용자에게 알린다.
- **`글을 하나도 찾지 못했습니다`** 가 나오면 게시판 마크업이 바뀐 것이다.
  `parsers.py` 를 고쳐야 하니 사용자에게 그렇게 알린다. 억지로 넘어가지 마라.
- **`[첨부뿐]`** 은 정상이다. LEET 공지는 대부분 내용이 .hwp 안에 있다.
- 마지막 줄의 `일정 추출 대기 N건` 을 확인한다. 0이면 3단계로 건너뛴다.

새 글이 있으면 이 단계에서 텔레그램 알림이 이미 나간다. 따로 보낼 것 없다.

---

## 2단계 — 일정 뽑기

`work/pending/` 의 `.txt` 파일을 **전부** 읽고, 각각에 대해 JSON 을 하나씩 쓴다.
규칙은 `automation/extract_prompt.txt` 에 전부 적혀 있다. **그 파일을 읽고
그대로 따르라.** 여기에 규칙을 다시 적지 않는 이유는, 두 곳에 적어 두면
한쪽만 고쳐져서 클라우드와 내 PC의 동작이 달라지기 때문이다.

특히 자주 틀리는 세 가지만 다시 강조한다:

1. **기간은 "시작"과 "마감" 두 건으로 쪼갠다.** 하나의 긴 일정으로 만들면
   D-3 알림이 시작일 기준으로 울려서 마감을 놓친다.
2. **연도가 없는 날짜**("8. 7.(금)")는 게시일을 기준으로 판단하되,
   게시일보다 두 달 이상 과거가 되면 내년이다. 요일로 검산하라.
3. **일정이 없어도 파일을 쓴다.** 안 쓰면 다음 실행 때 같은 글을 또 읽는다.

다 쓰고 나면 처리한 파일을 지운다:

```
rm work/pending/*.txt
```

## 3단계 — 캘린더 만들기

```
python build_ics.py
python build_ics.py --selftest
```

`--selftest` 가 실패하면 **절대 그냥 넘어가지 마라.** 아이폰이 캘린더 파일
전체를 거부하게 된다. 나오는 오류별 대처:

| 오류 | 원인 |
|---|---|
| `75옥텟 초과` | `fold()` 가 망가졌다 |
| `CRLF 가 아닌 줄바꿈` | git 이 파일을 건드렸다. `.gitattributes` 에 `*.ics -text` 가 있는지 확인 |
| `UTF-8 로 읽을 수 없습니다` | 줄 접기가 한글 한 글자를 반토막 냈다 |
| `UID 가 겹칩니다` | 서로 다른 글이 같은 slug 를 쓰고 있다 |

## 4단계 — 확인하고 알리기

사용자에게 이렇게 보고한다:

- 새 공지 몇 건 (제목과 게시판)
- 새로 잡은 일정 몇 건 (날짜와 내용)
- 자동 추출이 안 된 글이 있으면 그 사실과 이유

그다음 **다가오는 마감이 있는지 확인한다:**

```
python remind.py --list
```

오늘 알려야 할 것이 있으면 (`python remind.py --dry-run` 으로 미리 보고)
사용자에게 물어본 뒤 `python remind.py` 로 보낸다.

## 클라우드에 반영하기

내 PC에서 돌렸다면 결과를 저장소에 올려야 아이폰 캘린더에 반영된다.
**사용자에게 물어본 뒤** 커밋한다.

```
git add -A state docs
git commit -m "공지·일정 갱신"
git push
```

`work/` 와 `config.json` 은 올라가지 않는다(.gitignore). 정상이다.

## 자주 겪는 문제

**`텔레그램 설정을 찾을 수 없습니다`**
→ `python setup_telegram.py <봇토큰>` 을 먼저 실행한다.
   daily brief 의 봇이 아니라 **이 프로젝트 전용 봇**의 토큰이어야 한다.

**버튼을 눌렀는데 답이 없다**
→ `python bot_server.py --once` 로 밀린 클릭을 처리한다.
   클라우드에서는 10분마다 자동으로 처리된다. 텔레그램이 24시간 보관하므로
   클릭이 사라지지는 않는다.

**알림이 갑자기 수십 개 왔다**
→ `state/seen.json` 이 지워졌을 가능성이 높다. 저장소에서 되살리거나,
   `python scrape.py --seed-only` 로 현재 글을 전부 '본 것'으로 기록한다.

**게시판을 하나 더 추가하고 싶다**
→ `sources.py` 의 `TABS` 에 항목을 추가한다. 서강대와 같은 CMS(다른 학교
   상당수가 쓴다)면 `config_fk` 숫자만 바꾸면 되고, 완전히 다른 게시판이면
   `parsers.py` 에 파서 클래스를 하나 더 만들어야 한다.
   새 게시판은 첫 실행 때 조용히 기록만 하고 알림을 보내지 않는다.
